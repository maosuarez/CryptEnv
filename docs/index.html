Encrypted local store

CryptEnv documentation

A local-first vault for API keys, credentials, links, notes and shell commands. Everything is encrypted on your device and reachable from a desktop app, a CLI, a terminal UI, an MCP server for AI agents and a localhost REST API.

Download latest release CLI reference MCP setup
AES-256-GCMArgon2id127.0.0.1 onlyTauri 2 · RustMIT

The desktop app owns the vault: it holds the SQLite database, derives the key from your master password and serves an HTTPS API on 127.0.0.1:47821. Every other surface is a client of that API — none of them opens the database directly.

The desktop app must be running and unlocked for the CLI, TUI and MCP server to work. If a command says the vault is unreachable, start the app first and run crypt-env doctor.

02Core concepts#

Items

Encrypted vault rows of type secret, credential, link, note or command. Each can carry categories.

Projects

A named group of environments. Names are unique, case-insensitive.

Environments

e.g. local, staging, production. Each links vault items under env-var keys and has optional .env output paths.

Commands

Saved shell commands with {{VAR}} placeholders, resolved from arguments or the vault at run time.

An item is only "in" an environment when it is linked under a key (a real foreign key, not a name match). Linking happens when you add a variable, save the environment in the GUI, or import/receive items into it.

Environment names must match ^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$. Project names allow spaces and non-ASCII letters but reject path separators, control characters, reserved device names and leading/trailing dots or whitespace (max 128 chars).

Scope resolution#

Every scoped command (add, fill, inject, set, search, exec, list, cmd, sync, share send/receive/import, relay receive, tui) resolves its project and environment once, field by field:

  1. The --project / --env flags.
  2. crypt-env.json, searched from the current directory upwards (like .git).
  3. Fallback: project = current folder name, environment = that project's default environment.
crypt-env.json
{
  "project": "my-app",
  "environment": "production"
}

project is required, environment is optional. Only add auto-creates a missing project; every other command fails with a clear message instead of creating server state.

Global items#

Items marked global are reusable across projects (the GUI's Global Secrets view). Discovery surfaces — search, list, GET /items, GET /commands, the MCP list/search tools — union globals in by default and tag each row as linked, global or global+linked. Materialization surfaces — fill, inject, env example generation, LAN share — only ever use what is linked. Linking a global into an environment is always an explicit act.

03Client configuration#

The CLI, TUI and MCP server read three optional environment variables. The defaults work when client and app run on the same machine; overrides exist for split setups such as WSL ↔ Windows.

VariableDefaultEffect
CRYPTENV_API_URLhttps://127.0.0.1:47821REST base URL. Must be an absolute http/https URL. A non-loopback host prints a warning and proceeds.
CRYPTENV_CERT_PATHprobed under APPDATA → XDG_DATA_HOME → ~/.local/share + com.maosuarez.cryptenv/tls/cert.pemTLS certificate to pin. If set but unreadable the client errors — it never falls back or disables verification.
CRYPTENV_TOKEN_PATH%APPDATA%\com.maosuarez.cryptenv\.cli_token or ~/.local/share/com.maosuarez.cryptenv/.cli_tokenWhere the CLI caches its session token after unlock.

From WSL, crypt-env setup wsl persists these into your shell startup (see setup and the WSL ↔ Windows guide). On Windows the GUI offers the same under Settings → WSL Integration.

04CLI reference#

crypt-env talks to the running app. The first authenticated command prompts for your master password (hidden input) and caches a session token; later commands reuse it until it expires or the vault locks.

Items & env files#

crypt-env add [INPUT] [--file [PATH]] [--credential | --note] [--name NAME] [--force]

Adds a variable to the resolved environment. INPUT is KEY=value or $VARNAME (read from your shell). --file bulk-imports a .env (default ./.env). On an existing key it asks before updating the item in place; --force skips the prompt. Shared items (global, or linked elsewhere) are never rewritten silently — you get SHARED_ITEM_CONFLICT.

shell
crypt-env add "OPENAI_API_KEY=sk-..."
crypt-env add '$DATABASE_URL' --name DATABASE_URL
crypt-env add --file .env.local --project my-app --env staging
crypt-env add "ADMIN=user:pass" --credential

crypt-env fill [PATH] [-f | --force]

Fills a template with values from the resolved environment. With no PATH it looks for .env.example (writes sibling .env) then .env; if neither exists it generates a fresh .env from the environment's keys. Keys not in scope keep their original line. An existing file not created by CryptEnv is refused unless --force, which backs it up to <path>.bak first. No interactive prompt — safe in CI.

shell
crypt-env fill                      # .env.example → .env
crypt-env fill config/.env.example --env production
crypt-env fill .env --force         # overwrite an unmanaged file, keeps .env.bak

crypt-env sync [--example PATH] [--env PATH] [--dry-run] [--environment NAME]

Appends keys present in .env.example but missing from .env, without touching existing lines. Values come from the vault when found.

shell
crypt-env sync --dry-run
crypt-env sync --example .env.example --env .env.local --environment staging

crypt-env set NAME · crypt-env inject NAME [--shell pwsh|bash|zsh|sh]

Print a shell assignment to stdout so you can load one secret into the current shell. inject auto-detects the shell unless --shell is given.

shell
# bash / zsh
eval "$(crypt-env set OPENAI_API_KEY)"
# PowerShell
crypt-env inject OPENAI_API_KEY --shell pwsh | Invoke-Expression

crypt-env search QUERY [--scope-globals with|without|only]

Prints ID, TYPE, NAME, SCOPE, CATEGORIES. Never prints values.

shell
crypt-env search stripe
crypt-env search db --scope-globals only

Saved commands#

crypt-env memory "COMMAND"

Saves a command string; prompts for a name, an optional description and the shell. Use {{VAR}} for placeholders.

shell
crypt-env memory "docker compose -f docker-compose.{{ENV}}.yml up -d --build"

crypt-env list [-s REGEX] [--type TYPE] [--scope-globals with|without|only]

Lists saved commands (default type command) with a SCOPE column.

crypt-env exec NAME [--VAR=value ...] [--shell pwsh|bash]

Resolves placeholders and runs the command. If a linked and a global command share a name, the linked one wins and a warning is printed.

shell
crypt-env exec deploy --ENV=staging --REGION=us-west-2

crypt-env cmd [NAME] [--list] [--info] [--VAR=value ...]

All-in-one: --list lists commands, NAME --info shows description and placeholders, NAME --VAR=value runs it.

Sharing#

Three channels. All of them encrypt end to end; received items are owned by the target project and linked into the target environment (a key that already exists there is imported but not relinked, and reported).

LAN bridge

Same network. mDNS discovery, ECDH key exchange, both sides confirm a fingerprint.

Encrypted package

A .vault file plus a one-time passphrase. Send them over different channels.

Internet relay

AES-256-GCM + Argon2id passphrase, burn after read, 24 h TTL. Requires relay settings in the app.

shell
# LAN — items must be linked in the resolved environment
crypt-env share send 12 15
crypt-env share receive              # prompts for the pairing code

# Encrypted package
crypt-env share export 12 15 -o secrets.vault
crypt-env share import -f secrets.vault   # passphrase prompted, hidden

# Internet relay
crypt-env relay send --items 12,15
crypt-env relay receive --code X7K2-M9P4 --passphrase "..."

relay receive --passphrase ends up in shell history. Clear it or prefix the command with a space if your shell ignores those.

More detail: docs/sharing.md.

Run inside WSL when the vault lives on Windows. Writes ~/.config/cryptenv/env.sh and a marked block in your shell rc (with a one-time backup). --cert-path is required when the Windows APPDATA isn't forwarded into WSL. --remove undoes it.

shell

crypt-env doctor

Reports app reachability, version, vault lock state, token files and validates crypt-env.json if present.

06MCP server#

crypt-env-mcp is a Model Context Protocol server (JSON-RPC 2.0 over stdio) that lets AI assistants such as Claude Code, Claude Desktop or Cursor work with your vault. It is designed so the model can use secrets without seeing them: values are written to files or injected into processes, never returned in tool responses.

Setup#

  1. Open CryptEnv → Settings → Integrations → generate an MCP token. It is stored in the app data folder as mcp_token.
  2. Keep the app running and unlocked.
  3. Register the server in your MCP client and restart it. It is a stdio command — do not configure a url.
claude_desktop_config.json
{
  "mcpServers": {
    "cryptenv": {
      "command": "C:\\full\\path\\to\\crypt-env-mcp.exe"
    }
  }
}
claude code
claude mcp add cryptenv -- crypt-env-mcp

On Windows the installer puts crypt-env-mcp.exe on your PATH; use where crypt-env-mcp to get the absolute path if your client needs one.

07REST API#

The app serves HTTPS on https://127.0.0.1:47821, bound to loopback only. The CLI, TUI and MCP server are built on it; you can call it from your own scripts too. Errors come back as {"error": "...", "code": "..."}.

Auth & TLS#

  • TLS: a self-signed certificate is generated on first launch at <app data>/com.maosuarez.cryptenv/tls/cert.pem. Pass --cacert with that file (or -k for quick tests).
  • Token: send X-Vault-Token with either a session token from POST /unlock (expires) or the static MCP token from Settings.
  • Tokens are compared in constant time. /unlock is rate-limited to 5 attempts per 60 s (429 RATE_LIMITED with Retry-After).

Write-target gating#

Files written by /fill, /environments/:id/inject and /environments/:id/example start with a marker line:

.env
# crypt-env: managed file (project: my-app, environment: production)
  • An existing file without the marker is foreign. Writing to it via output_path/output_dir returns 409 TARGET_EXISTS unless overwrite: true.
  • With overwrite: true the old content is copied to <path>.bak first (409 BACKUP_EXISTS if a backup is already there).
  • Paths configured on the environment itself are always written through, with the same backup, and reported in unmanagedPaths.
  • Names derived from output_dir are contained to that directory (422 PATH_NOT_CONTAINED otherwise).

Add *.bak to .gitignore wherever CryptEnv writes.

Examples#

bash
CERT="$HOME/.local/share/com.maosuarez.cryptenv/tls/cert.pem"   # Windows: %APPDATA%\com.maosuarez.cryptenv\tls\cert.pem
API=https://127.0.0.1:47821

# Unlock → session token
TOKEN=$(curl -s --cacert "$CERT" -X POST $API/unlock \
  -H 'Content-Type: application/json' \
  -d '{"master_password": "..."}' | jq -r .token)

# List items in a project/environment
curl -s --cacert "$CERT" "$API/items?project=my-app&environment=production" \
  -H "X-Vault-Token: $TOKEN"

# Create an item linked as DB_HOST
curl -s --cacert "$CERT" -X POST "$API/items?environment_id=1" \
  -H "X-Vault-Token: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"type": "secret", "name": "DB_HOST", "value": "localhost", "key": "DB_HOST"}'

# Fill a template into a file
curl -s --cacert "$CERT" -X POST "$API/fill?project=my-app&environment=production" \
  -H "X-Vault-Token: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"template": "DB_HOST=\nPORT=3000\n", "output_path": "/abs/path/.env"}'

# Write an environment to its configured paths
curl -s --cacert "$CERT" -X POST $API/environments/1/inject \
  -H "X-Vault-Token: $TOKEN" -H 'Content-Type: application/json' -d '{}'

Full contract, edge cases and known limitations: docs/reference.md.

08Security model#

Encryption at rest

Each item is encrypted with AES-256-GCM using a key derived from your master password with Argon2id. Deletes are zeroed on disk (secure_delete).

Volatile keys

The master password and derived key live in memory only while unlocked and are zeroized on lock. Auto-lock after a configurable timeout.

Local-only API

Loopback binding, TLS, token auth with constant-time comparison, rate-limited unlock.

No plaintext leaks

Values never appear in logs, errors or list responses. Reveal requires an explicit confirm; the MCP server writes or injects instead of returning.

Report vulnerabilities privately as described in SECURITY.md.

09Troubleshooting#

SymptomFix
